# Theme Integration Decisions

## Implementation boundaries
The test theme lives in `theme/`. Homecraft's starter runtime is imported unchanged alongside a thin PHP adapter and JavaScript integration modules. JavaScript remains responsible for scene behavior and browser state. PHP provides native Typecho data/URLs and safely serialized public configuration.

| Area | Files | Responsibility |
| --- | --- | --- |
| Upstream runtime | `theme/engine`, `theme/world`, `theme/vendor`, `theme/assets` | Unchanged pinned source; inventory in `UPSTREAM-FILES.json` |
| Adapter | `theme/functions.php`, shared header/footer and thin index/archive/post/page/404/scene templates | Native settings/URLs, server HTML and bootstrap projection |
| Integration | `theme/js/app.js`, `bootstrap.js`, `reading.js`, `fallback.js`, `home-config.js`, `traveller.js`, `scene.js` | Validate contract version, supply `@config`, load the scene, expose failure navigation |
| Presentation | `theme/css/scene.css`, `reading.css` | Independent fallback entry and minimal reading styles |
| Development | `dev/`, `tests/phase1.cjs` | Disposable Typecho and actual browser integration checks |

The starter island is the reversible POC baseline, not a final art-direction decision. Phase 4 adds native theme settings and configurable public summaries; Phase 5 adds native comments on reading routes; production packaging remains pending.

## Homepage and native blog route
Use a normal published Typecho page with `template=scene.php` (registered using `@package custom`), selected through native Reading settings as `frontPage=page:<cid>`, and enable `frontArchive`. This preserves native initialization, header/footer hooks and article/archive routing. Select a collision-free archive path during installation. `/blog/` is used only in the synthetic test database. PHP generates the URL with `Typecho\Router::url('archive', [], $options->index)`.

An initially investigated `frontPage=file:scene.php` returns before both theme functions and feed-field initialization in Typecho 1.3.0. Real HTTP validation exposed an uninitialized `archiveFeedUrl` failure when calling native `header()`. We rejected that route for the current POC rather than mutating private fields or duplicating core header behavior. The ordinary page approach must be used by the test seed. Theme switch/rollback guidance will need to restore previous Reading settings explicitly.

## Bootstrap contract v1
Server emits one non-executable `<script type="application/json" id="homecraft-bootstrap">` before module evaluation. Encode with PHP JSON_HEX_TAG, JSON_HEX_AMP, JSON_HEX_APOS, JSON_HEX_QUOT and JSON_THROW_ON_ERROR. Do not concatenate JavaScript source from settings.

```json
{
  "schemaVersion": 1,
  "view": { "kind": "home", "sceneEnabled": true },
  "site": { "title": "Example", "description": "", "url": "https://example.invalid/", "language": "zh-CN" },
  "urls": {
    "themeBase": "https://example.invalid/usr/themes/homecraft-typecho/",
    "home": "https://example.invalid/",
    "blog": "https://example.invalid/index.php/blog/",
    "feed": "https://example.invalid/index.php/feed/"
  },
  "scene": {
    "name": "Example", "skin": "", "languages": ["zh"],
    "weather": null, "dock": ["blog", "about", "phone"],
    "mailbox": { "endpoint": "", "email": "", "turnstileSitekey": "" },
    "badge": true
  },
  "posts": [],
  "pagination": null
}
```

- `view.kind`: home, post, page, archive, search or notFound. `themeBase` is an absolute URL ending in `/`.
- Phase 2 serializes this contract on every view. `app.js` validates it, then dynamically selects scene or reading integration. Reading templates remain server-rendered and do not import the scene.
- Phase 3 populates `posts` on scene views with the newest ten strictly public summaries; reading views keep it empty. Entries are `{id,title,url,publishedAt,excerpt}` with numeric ID, plain-text title/excerpt, native absolute permalink and ISO-8601 publication date. Filter published, already released, non-password-protected posts on the server before limiting. Never copy raw rows or logged-in private archive results.
- Phase 3 list/search views populate `pagination` using native totals and generated adjacent links; other views use null. The shape is `{currentPage,totalPages,previousUrl,nextUrl}`, numeric 1-based pages and URL-or-null links generated by native routing.
- Comments/forms and their tokens stay in native HTML. User emails, credentials, password fields, private bodies and raw database records never enter this contract.
- `home-config.js` explicitly projects `scene` fields; `portal.directory=[]` prevents directory loading during this local-only POC.

## Scene boot and fallback
The import map resolves Three.js, world modules, engine modules and `@config` to absolute theme URLs. The adapter does not rewrite upstream engine imports. Keep required `#world`, `#pages` and `#loading .bar > i`; allow upstream `mountHud()` to create its own UI.

The loading navigation is server-rendered above the overlay and does not depend on a running scene. Explicit `?plain=1` avoids importing 3D JavaScript. No-JavaScript CSS exposes the content cards. Dynamic import rejection exposes fallback content; asynchronous startup is separately observed via upstream `__home` / `__homeStartupError`. A slow-start notice after 30 seconds keeps navigation available without claiming to cancel the engine. Upstream handles hidden-tab rendering, but full scene destruction and pausing during card reading remain later lifecycle work.

Native links in scene cards lead to canonical conventional pages. Do not place comment forms in cards: upstream clones their HTML into a dialog and can duplicate IDs or lose script state.

## Site identity adapter and future portal metadata
Upstream `engine/traveller.js` asks `readSiteInfo(location.href)` for site-relative `homecraft.json`. A theme-directory file cannot satisfy that request. During initial tests it produced a non-blocking 404/timeout.

The selected import map now maps the exact absolute URL of `engine/traveller.js` to `js/traveller.js`. Both upstream consumers (`main.js` and `portal.js`) resolve to the same module/session. This thin adapter preserves the named `traveller` and `wornSkin` exports and delegates all travel-session behavior to upstream `createTravelSession`; only the site's own title source changes to safe CMS bootstrap data. It does not monkey-patch fetch, alter upstream files or duplicate session/history logic.

Phase 1 tests assert that the integration adapter is requested and that no self `homecraft.json` request occurs. Public metadata for visitors from other worlds is a separate future requirement: an explicit native metadata route/server mapping must work for root/subdirectory and permalink modes before claiming cross-site portal compatibility. Local directory loading remains disabled in the POC.

## Phase 2 module lifecycle
`header.php` outputs the same bootstrap contract on all views and only emits engine CSS/import maps for scene views. `footer.php` emits one `app.js` entry. Bootstrap validation rejects unsupported versions and unsafe URL protocols before dispatch. `scene.js` exports a guarded `startScene(data)`; it no longer self-starts on import. `reading.js` only enhances current-page navigation and imports no scene modules. Shared error handling leaves server-rendered content/navigation available.

`data-enhanced="true"` indicates frontend entry initialization, not successful asynchronous 3D startup; check upstream `__home.player` and the loading state for scene readiness. All public URL generation remains on the native Typecho side. See `PHASE2-REPORT.md` for root/subdirectory evidence and known untested modes.

## Phase 3 native content
`inc/public-posts.php` uses a native content widget with visibility/password/time filters before the ten-post limit. `js/content.js` enhances the server-rendered summary list using safe DOM text nodes. Reading templates retain native content/password gates and taxonomy/author/month links; search and pagination remain Typecho-owned. See `CONTENT-INTEGRATION.md` for the data boundary, native pagination projection, fixture setup and permalink-mode tests.

## Phase 4 additive contract and adapters
Bootstrap v1 now optionally includes `profile: {name,introduction,logo,favicon,links}` and `pages: {about,guestbook}`. Each profile link is `{id,name,url}` with an allowlisted id; each mapped page is null or `{title,url}`. JavaScript validates these additions while accepting earlier v1 data without them. Settings use request-local normalization and native page filtering; no raw page body is serialized. The recent-summary limit is now configurable from 1–20 (default 10).

The exact `@world/layout.js` import maps to `js/world-layout.js`, which reexports the unchanged upstream layout and removes the mailbox station/object unless a valid guestbook is mapped. `home-config.js` asynchronously validates configured skin dimensions/CORS before exposing it through `@config`; failure or a five-second timeout returns the default skin. Settings never configure an email-mailbox endpoint or credentials. Reading mode delegates to the native archive before rendering the header, or renders a conventional summary fallback if no front archive exists. See SETTINGS.md for administration and validation behavior.

## Phase 5 reading and native feedback
Post/page templates include a native Comments Archive widget and normal feedback form. Comments, user fields and security tokens stay in HTML and are not serialized into bootstrap. Native recursive rendering, moderation visibility and pagination remain server-controlled. The custom threaded callback omits remote avatars and adapts only the fallback reply href to avoid Typecho 1.3 comment-page redirects losing replyTo. Native inline reply and anti-spam scripts continue through the existing header hook.

`reading-content.js` enhances reading-only pages with local scrolling, copy controls and a submit-event/pageshow safeguard; there is no AJAX route, router or browser draft store. See READING-COMMENTS.md and PHASE5-REPORT.md for tested recovery, no-JavaScript behavior and compatibility limits.
